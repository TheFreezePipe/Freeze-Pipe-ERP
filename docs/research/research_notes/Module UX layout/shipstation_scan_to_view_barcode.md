# ShipStation "Scan to View" Barcode: Exact Payload, Scan Page Behavior, API Availability, and Reproduction on ERP Tote Labels (as of Oct 2026)

Research date: 2026-10-19. Official help-center articles were pulled through the Zendesk JSON API (`help.shipstation.com/api/v2/help_center/en-us/articles/{id}.json`); "updated" dates quoted are the article `updated_at` values. The ShipStation Community forum now returns "Access Denied" without login (Gainsight migration), so the key community post was read from the Wayback Machine capture of 2025-03-23.

**Bottom line (one sentence):** the Scan to View barcode is a Code 128 symbol whose decoded text is `^#^` + (ShipStation V1 `orderId` in hexadecimal) + `^`, e.g. orderId 1234567890 becomes `^#^499602D2^`. The ERP can build it from the `shipstation_orders.shipstation_order_id` (bigint) it already stores, with no extra API call. The format is documented only by one community post. ShipStation does not document it officially, so a 5-minute bench test (below) must confirm it before rollout.

---

## Q1. What does the Scan to View Barcode encode (payload, symbology, legacy vs new layout)?

### Takeaway
According to a March 2025 ShipStation Community post by a user who rebuilt it for a 3PL integration, the decoded string is the literal prefix `^#^`, then the ShipStation **orderId** (the internal system ID, not the order number) in hex, then the literal suffix `^`. It is printed as Code 128 (Code128Auto by default, and every character fits in subset A or B). ShipStation's own docs name the field `[Barcode]` and never describe its contents. Nothing I found shows the format changed between the Legacy and new layouts.

### Cited Findings
- **Payload format (community, primary source for the encoding):** A post titled "ShipStation Scan to View Barcode Information" (user d-a-v-i-s, posted 03-10-2025) says: "The contents of a ShipStation Scan to View barcode consist of 3 parts; Prefix, Content, and Suffix". The prefix is "The literal characters "^#^"", the content is "The ShipStation Order ID, encoded to hexidecimal format", and the suffix is "The literal character "^"". Worked example: Order ID `1234567890`, hex `499602D2`, giving `^#^` + `499602D2` + `^`. — [ShipStation Community (Wayback 2025-03-23)](http://web.archive.org/web/20250323074305/https://community.shipstation.com/t5/ShipStation-Features/ShipStation-Scan-to-View-Barcode-Information/td-p/27185) (live URL now login-gated: [community.shipstation.com](https://community.shipstation.com/t5/ShipStation-Features/ShipStation-Scan-to-View-Barcode-Information/td-p/27185))
- **Why the post exists:** "We recently found ourselves needing to recreate the ShipStation Scan to View barcode for an integration with our third party warehouse. The ShipStation documentation provides very little information on the content of this barcode". — [same post](http://web.archive.org/web/20250323074305/https://community.shipstation.com/t5/ShipStation-Features/ShipStation-Scan-to-View-Barcode-Information/td-p/27185)
- **Symbology (community):** "ShipStation expects the Code128Auto barcode format. In practice, the barcodes can always be encoded in the "B" Codeset". The post also notes that start, stop and checksum characters "would typically be automatically generated by barcode encoding software". — [same post](http://web.archive.org/web/20250323074305/https://community.shipstation.com/t5/ShipStation-Features/ShipStation-Scan-to-View-Barcode-Information/td-p/27185)
- **orderId vs orderNumber (community):** "The ShipStation Order ID is not the same as the ShipStation Order Number. It's a unique identifier accessible via the ShipStation API or viewable via the UI as the numerical string in the URL when viewing a ShipStation order." — [same post](http://web.archive.org/web/20250323074305/https://community.shipstation.com/t5/ShipStation-Features/ShipStation-Scan-to-View-Barcode-Information/td-p/27185)
- **Official template markup:** To add it to a custom template, add `<p align="center"><barcode size="small">[Barcode]</barcode></p>` "to either the Order Header or the Order Footer". The barcode also only prints if Document Options has "Include "Scan to View" Barcode on Packing Slips" checked. — [How do I add a Scan to View barcode to a custom packing slip template? (updated 2026-01-07)](https://help.shipstation.com/hc/en-us/articles/360045864251-How-do-I-add-a-Scan-to-View-barcode-to-a-custom-packing-slip-template)
- **Default template line:** "If you used a copy of the Default Template, you will see a line of code near the bottom: `<barcode size="small">[Barcode]</barcode>`". — [Add Barcodes to Packing Slips (updated 2026-10-13)](https://help.shipstation.com/hc/en-us/articles/360060970712-Add-Barcodes-to-Packing-Slips)
- **Official definition (function only, no encoding):** "ShipStation's Scan to View barcode is a special barcode added to your packing slips that allows you to open the order's Order Details screen from anywhere in the ShipStation interface." It also "is the default barcode that appears as the last element of ShipStation's default packing slips". — [View Orders with a Barcode Scan (updated 2025-06-05)](https://help.shipstation.com/hc/en-us/articles/360025870412-View-Orders-with-a-Barcode-Scan)
- **Default symbology and supported types:** "Here's the packing slip HTML of a barcode that has a different size, type, and height than the default barcode (Code128Auto)". Supported `barcodetype` values include Code128Auto (default), Code128A, Code128B, Code128C, Code39, Code93, EAN13, UPCA, GS1 DataBar and more. Sizes are x-small (font 12), small (24), medium (36), large (60), x-large (72), or 10–100. `height` runs 1–7 with 3 as default, and `humanreadable` is none (default), top or bottom. — [Add Barcodes to Packing Slips](https://help.shipstation.com/hc/en-us/articles/360060970712-Add-Barcodes-to-Packing-Slips)
- **Code128C misreading note (official, applies to numeric Order # barcodes):** "if you ship more than 11,000 shipments, or if your store's order numbers include a long sequence of zeros, such as 10000000034, you will need to use the barcodetype ="Code128A" instead of the default Barcode Type 128c". Also: "The default barcode type 128c has inconsistencies with long sequences that can cause an error when a barcode has 4 trailing Zeros", with examples such as "10000000034 scanned as "11000"" and "111000 ... scanned as: "wouldn't load" or "barcode type Code128C doesn't support some or all of the characters"". The same text appears in [Troubleshoot Packing Slips](https://help.shipstation.com/hc/en-us/articles/360035963492-Troubleshoot-Packing-Slips) under "Packing Slip Barcode Scan Fails". — [Add Barcodes to Packing Slips](https://help.shipstation.com/hc/en-us/articles/360060970712-Add-Barcodes-to-Packing-Slips)
- **Contradiction in the official docs:** One section calls 128C "the default" while the parameter table says the default is Code128Auto. — [Add Barcodes to Packing Slips](https://help.shipstation.com/hc/en-us/articles/360060970712-Add-Barcodes-to-Packing-Slips)
- **Third-party template using Code128A for `[Barcode]`:** GroovePacker's ShipStation guide gives the Scan to View markup as `<p align="center"><barcode size="medium" barcodetype="Code128A">[Barcode]</barcode></p>` and says "The designation for using barcodetype (barcodetype="Code128A") is optional but has been recommended by ShipStation support". — [GroovePacker Support (modified 2020-06-30)](https://groovepacker.freshdesk.com/support/solutions/articles/6000096004-how-can-i-add-a-barcode-to-my-shipstation-packing-slip-)
- **Field-replacement list (official):** The packing-slip table has no `[Barcode]`, `[Order Barcode]`, `[Order Number Barcode]` or `[Shipment Barcode]` entries. The identifier-related entries are:
  - `[Order #]`: "The order number as displayed in ShipStation"
  - `[Scan Order #]`: "The order number without any dashes, typically used for barcodes"
  - `[Order ID]`: "The Order ID sent to ShipStation from the selling channel (visible via ShipStation's API)"
  - `[Import Key]`: "The import key for the individual order (in most cases, this will be the same as the order number)"

  `[Barcode]` is documented only in the barcode articles. — [Field Replacements in Custom Templates (updated 2026-08-12)](https://help.shipstation.com/hc/en-us/articles/4403180517275-Field-Replacements-in-Custom-Templates)
- **Legacy and new layout both use the Scan to View barcode:** Scan to Print exists in both layouts, and both sets of steps say "Scan a packing slip barcode for an order". — [Verify & Print Shipments with Barcode Scan (updated 2026-08-09)](https://help.shipstation.com/hc/en-us/articles/360031021831-Verify-Print-Shipments-with-Barcode-Scan)
- **Historical V3 scan bug:** A May 2022 community user reported "in ShipStation V3, the order barcodes do not scan" on order summaries. This was during the new-layout ("V3") rollout. — [Pick List Order Number Barcode thread (Wayback 2025-05-19)](http://web.archive.org/web/20250519203435/https://community.shipstation.com/t5/ShipStation-Features/Pick-List-Order-Number-Barcode/m-p/13177)

### Inferences
- **The format is very likely right.** The community post (March 2025, when the new layout was already the default) is consistent with ShipStation support's long-standing advice to use `Code128A` for `[Barcode]`. That advice only works if the payload contains no lowercase letters. `^` (ASCII 94), `#` (35), digits and uppercase A–F all sit in both Code 128 subset A and subset B, so the payload is only valid in A if the hex is uppercase. The post's example `499602D2` is also uppercase.
- **The `^#^ … ^` wrapper is probably a sentinel.** It most likely lets ShipStation's global keyboard listener tell a Scan to View scan apart from ordinary typing. That fits the official statement that it opens Order Details "from anywhere in the ShipStation interface", while "Other types of barcodes require the barcode search pop-up to be active" ([Troubleshoot Packing Slips](https://help.shipstation.com/hc/en-us/articles/360035963492-Troubleshoot-Packing-Slips)). This is my inference; ShipStation does not say it.
- **Code128C cannot encode this payload.** It contains non-digits. The official Code128C trailing-zeros warning is therefore about numeric `[Order #]` barcodes, not Scan to View.
- **Which subset you print does not matter, only the decoded text.** Scanners send the decoded characters, not the subset, so Code128A, Code128B and Code128Auto symbols with the same data are interchangeable for ShipStation.

### Gaps
- **UNVERIFIED (no official source):** the `^#^` + hex(orderId) + `^` format, whether hex letters must be uppercase or are matched case-insensitively, and whether short hex values are zero-padded. The only example is 10 decimal digits, which gives 8 hex digits naturally. An orderId below 268,435,456 would give 7 hex digits, e.g. `^#^75BCD15^`, and padding behavior is unknown.
- **No official changelog or statement** on whether the payload changed between Legacy and the new layout. The only evidence that it is current is the March 2025 post date and the unchanged `[Barcode]` docs through 2026.
- I could not find any field-replacement docs listing `[Order Barcode]`, `[Order Number Barcode]` or `[Shipment Barcode]`. They don't appear in the current official field-replacement table and may be old or misremembered names.
- **5-minute bench test:**
  1. Open Notepad on the bench laptop and scan a current packing slip's Scan to View barcode with the same scanner. With carriage return on, one line appears.
  2. Read the raw string and compare it to `'^#^' + orderId.toString(16).toUpperCase() + '^'` for that order's `shipstation_order_id` in the ERP.
  3. Repeat with an order whose orderId is below 268,435,456 if one exists (to test padding).
  4. Hand-build a lowercase-hex version and scan it into the Scan page (to test case-sensitivity).

## Q2. Which identifier does the Scan page accept? Collisions, prefix matches, ambiguity, post-label scans

### Takeaway
The official Scan workflows accept "a Scan to View Barcode or an order number barcode", and the order number can also be typed. Because the Scan to View barcode carries the system orderId, it identifies exactly one order record no matter which store it came from. An order-number barcode can collide across the two Shopify stores, and ShipStation does not document what the Scan page does when a number matches several orders or matches as a prefix. Scanning the same packing-slip barcode after the label exists reopens the shipment for history or reprint. I found no separate "shipment barcode".

### Cited Findings
- **Requirements for all Scan workflows:** "Packing slips with a Scan to View Barcode or an order number barcode." — [Verify & Print Shipments with Barcode Scan](https://help.shipstation.com/hc/en-us/articles/360031021831-Verify-Print-Shipments-with-Barcode-Scan)
- **Scan to Print (new layout):** "Go to the Scan tab." … "Scan a packing slip barcode for an order. This will open the order's shipment details." … "Click Print Label or use the P hotkey". Also "ShipStation will immediately be ready for you to scan your next packing slip barcode." — [Verify & Print](https://help.shipstation.com/hc/en-us/articles/360031021831-Verify-Print-Shipments-with-Barcode-Scan)
- **Scan to Verify / Verify & Print:** "Scan a barcode from your packing slip or enter the order number manually to open the order you wish to verify." These two workflows are "only available in ShipStation's new layout." — [Verify & Print](https://help.shipstation.com/hc/en-us/articles/360031021831-Verify-Print-Shipments-with-Barcode-Scan)
- **Conflicting official statement:** "If you plan to use the Scan to Print feature, your packing slip must include the Scan to View Barcode." — [Create Custom Packing Slips (Document Options section)](https://help.shipstation.com/hc/en-us/articles/360057378051-Create-Custom-Packing-Slips). This conflicts with the "or an order number barcode" wording above.
- **Post-label behavior:** "To view an order's history or to reprint a label, scan the barcode on the packing slip again while in the Scan to Verify & Print screen." Also: "If you scan the packing slip for an order with a label already generated, you can print the existing label by pressing P or scanning the Purchase and Print Label barcode." — [Verify & Print](https://help.shipstation.com/hc/en-us/articles/360031021831-Verify-Print-Shipments-with-Barcode-Scan)
- **Print-action barcode:** "Click Print Barcode Sheet in the Scan to Verify & Print screen. This will print the Scan to Print Barcode, which you can keep at your workstation. Scan this barcode to purchase and print the labels for each order". — [Verify & Print](https://help.shipstation.com/hc/en-us/articles/360031021831-Verify-Print-Shipments-with-Barcode-Scan)
- **Barcode Search (Orders tab) accepts both IDs:** "Scan to Search allows you to scan a custom barcode containing either the Order # or Order ID so ShipStation can perform the action you designate: view the order, ship the order, or add order to a batch". You first "Select the order status in which you want to search" (hotkey Ctrl+Shift+S). — [Search Orders with a Barcode Scan (updated 2026-05-05)](https://help.shipstation.com/hc/en-us/articles/360026158631-Search-Orders-with-a-Barcode-Scan)
- **Scan to View works from anywhere; other barcodes need the pop-up:** "ShipStation requires the Scan to View barcode to display an order's details on scan if you are not in the Barcode Scanning screen." And: "Other types of barcodes require the barcode search pop-up to be active for the barcode scan to function in ShipStation." — [Troubleshoot Packing Slips](https://help.shipstation.com/hc/en-us/articles/360035963492-Troubleshoot-Packing-Slips)
- **Mobile app difference:** "The Scan to View barcode will pull up that order's details." Other barcodes act "more like a search and bring up a list of orders that fit the parameters". — [Scan Barcodes with ShipStation Mobile (updated 2026-05-05)](https://help.shipstation.com/hc/en-us/articles/360026491471-Scan-Barcodes-with-ShipStation-Mobile)
- **orderId uniqueness:** The V1 Order model defines `orderId` as "The system-generated identifier for the order", while `orderNumber` is "A user-defined order number used to identify an order". — [ShipStation V1 API: Order model](https://www.shipstation.com/docs/api/models/order/)
- **Recommended scanners:** "Models we've tested that work well include the Zebra Symbol LS2208 and the Motorola LI4278". The docs also recommend enabling the scanner's carriage return ("Enter") suffix. — [Verify & Print](https://help.shipstation.com/hc/en-us/articles/360031021831-Verify-Print-Shipments-with-Barcode-Scan)

### Inferences
- **The Scan to View payload is the right choice for two stores.** It encodes the account-unique orderId and opens one specific order record, so a duplicate order number across the two Shopify stores cannot open the wrong order. An order-number barcode gives up exactly that.
- **The packing slip carries no separate shipment barcode.** After the label is bought, the same Scan to View barcode reopens the order or shipment for reprint. The tote label therefore never needs a second barcode for the post-label step.

### Gaps
- **UNVERIFIED:**
  - What the Scan tab does when a scanned or typed order number matches more than one order (two stores), or matches as a prefix (e.g. `1001` vs `1001-1`). It might show a picker, open the first match, or fail. No official or community source was found. **Bench test:** create two manual orders with the same order number in different stores, scan or type that number on the Scan tab, and record the result.
  - Whether the Scan tab accepts an orderId typed in decimal without the wrapper. Undocumented; not needed if the wrapper format is used.
  - How the Scan tab treats cancelled or shipped orders. Barcode Search uses an explicit status filter, but the Scan tab docs are silent.

## Q3. Is the barcode value available per order through the API? Can the ERP construct it?

### Takeaway
No API exposes a "barcode" or "scanToView" field: neither the V1 Order or AdvancedOptions models, nor (from the docs index) V2. But the payload is a pure function of the V1 `orderId`, which every V1 `GET /orders` and webhook-fetched order includes, and which the ERP already stores in `shipstation_orders.shipstation_order_id` (bigint, UNIQUE). So the ERP can build the barcode string for every imported order at import time, or on the fly, with no extra call and no packing-slip PDF.

### Cited Findings
- **V1 Order model identifiers:**
  - `orderId` (read-only): "The system-generated identifier for the order."
  - `orderNumber`: "A user-defined order number used to identify an order."
  - `orderKey`: "A user-provided key that should be unique to each order", which "Can only be initialized during order creation".

  The model has no barcode field. — [ShipStation V1 API: Order model](https://www.shipstation.com/docs/api/models/order/)
- **V1 AdvancedOptions model:**
  - `mergedOrSplit`: "Returns whether or not an order has been merged or split with another order."
  - `mergedIds`: "Each orderId identifies an order that was merged with the associated order."
  - `parentId`: "If an order has been split, it will return the Parent ID of the order with which it has been split."
  - `storeId`: "ID of store that is associated with the order."

  No barcode field. — [ShipStation V1 API: AdvancedOptions model](https://www.shipstation.com/docs/api/models/advanced-options/)
- **V2 docs:** The ShipStation API v2 documentation index (`llms.txt`) lists shipments, labels, label documents, batches and so on, with no "packing slip" or "barcode" entries. A grep for "packing|slip|barcode" returned nothing. — [docs.shipstation.com/llms.txt](https://docs.shipstation.com/llms.txt)
- **What the ERP stores today (local code, not a web source):**
  - `supabase/functions/shipstation-webhook/index.ts` types `orderId: number` and upserts `shipstation_order_id: order.orderId` along with `store_id: order.advancedOptions?.storeId`.
  - The baseline migration declares `shipstation_order_id bigint NOT NULL` with constraint `shipstation_orders_shipstation_order_id_key UNIQUE (shipstation_order_id)` (`supabase/migrations/20260504000001_baseline_schema_from_staging.sql`, lines ~3352 and ~3926).
- **Shopify order import split by default:** "Shopify orders now import as split shipments by default. If you want to merge them, enable Consolidate Shopify multi-fulfillment orders into a single ShipStation order". — [Shopify: Changes to Order Import (updated 2026-10-13)](https://help.shipstation.com/hc/en-us/articles/47307773375387-Shopify-Changes-to-Order-Import)

### Inferences
- **Construction rule for the ERP** (TypeScript/Deno; orderId fits safely in a JS number up to 2^53):
  ```ts
  const scanToView = (orderId: number | bigint) =>
    `^#^${orderId.toString(16).toUpperCase()}^`;
  // 1234567890 -> "^#^499602D2^"
  ```
  This could be a generated column or a view expression in Postgres, e.g. `'^#^' || upper(to_hex(shipstation_order_id)) || '^'`. `to_hex` accepts bigint. That makes the value "automatically available with every imported order", as the brief asks.
- **The packing slip PDF is not needed as a source of truth.** The ERP does not need to fetch or parse ShipStation packing slips; I found no V1 or V2 endpoint that returns them.
- **Watch for split Shopify imports.** Each split order or shipment in ShipStation is likely its own V1 order record with its own `orderId` (linked by `advancedOptions.parentId`). The ERP must print one tote label per ShipStation order record, not per Shopify order, or the packer will open only part of it.

### Gaps
- I did not exhaustively confirm that V1 has no packing-slip endpoint; none appears in the model docs reviewed. ShipStation's V1 docs site was not fully enumerated.
- **UNVERIFIED:** whether the new layout's order URL still shows the V1 `orderId`. The community post says the UI URL shows it, which was certainly true in Legacy. This does not matter for the ERP because it has `orderId` from the API.

## Q4. How to generate an identical symbol

### Takeaway
Encode the exact string `^#^{HEX}^` (uppercase hex of orderId, no spaces, no control characters inside) as Code 128. Subset B, or A, or Auto all give the same decoded text. Print it with enough quiet zone at roughly ShipStation's default size, and set the scanner to send Enter after each scan. The only control character involved is the scanner's own CR suffix, not anything in the symbol. ShipStation has no official statement endorsing third-party-printed Scan to View barcodes, but one community user did it for a 3PL, and GroovePacker reads and reuses ShipStation's barcode.

### Cited Findings
- **Exact composition:** "The Prefix, Content, and Suffix are then concatenated together and encoded in the Code128 barcode format." The post links Wikipedia's Code 128 page and the Google font "Libre Barcode 128" as references. — [ShipStation Community post (Wayback)](http://web.archive.org/web/20250323074305/https://community.shipstation.com/t5/ShipStation-Features/ShipStation-Scan-to-View-Barcode-Information/td-p/27185)
- **Real-world third-party reproduction:** The same post was written because the author needed to "recreate the ShipStation Scan to View barcode for an integration with our third party warehouse". — [same post](http://web.archive.org/web/20250323074305/https://community.shipstation.com/t5/ShipStation-Features/ShipStation-Scan-to-View-Barcode-Information/td-p/27185)
- **GroovePacker reads the ShipStation barcode:** "GroovePacker can now read the ShipStation "scan to view" barcode". — [GroovePacker Support](https://groovepacker.freshdesk.com/support/solutions/articles/6000096004-how-can-i-add-a-barcode-to-my-shipstation-packing-slip-). GroovePacker also says the Scan to View barcode "eliminates the need to use the search bar and opens the order directly using a scan". — [GroovePacker: Scan Pack Ship extension (deprecated)](https://groovepacker.freshdesk.com/support/solutions/articles/6000194419-using-the-shipstation-scan-pack-ship-chrome-extension-depreciated-)
- **ShipStation's general stance on custom barcodes:** "You can add your own custom barcodes that contain ShipStation order data, like order numbers, to print on your packing slips. You can then use these barcodes in other parts of your workflow." — [Barcode Scanning Overview (updated 2025-11-06)](https://help.shipstation.com/hc/en-us/articles/360026158591-Barcode-Scanning-Overview)
- **Size and troubleshooting guidance:**
  - Default size is `small` (font size 24).
  - "Change the value for the barcode size to x-small. Sometimes a part of barcode code gets cut off if the print is too large causing an error when reading it."
  - "the barcode size could be too small for the reader. Try adjusting the barcode size to make it bigger."

  — [Add Barcodes to Packing Slips](https://help.shipstation.com/hc/en-us/articles/360060970712-Add-Barcodes-to-Packing-Slips); [Troubleshoot Packing Slips](https://help.shipstation.com/hc/en-us/articles/360035963492-Troubleshoot-Packing-Slips)
- **GitHub search:** `gh search code` for `shipstation "^#^"`, `shipstation "scan to view"` and similar returned no ShipStation implementations. I found no open-source integration (SkuVault, SKULabs, Shippo, etc.) publishing this format.

### Inferences
- **Sample payloads** (computed from the rule):
  - 1234567890 gives `^#^499602D2^` (12 characters)
  - 987654321 gives `^#^3ADE68B1^`
  - 123456789 gives `^#^75BCD15^` (11 characters; padding behavior unverified)
- **Symbol width** (my arithmetic from the standard Code 128 structure: 11 modules per symbol, 13-module stop, at least 10X quiet zones):
  - A 12-character payload is start + 12 data + check + stop. That is (14 × 11) + 13 = 167 modules, or about 187 modules with quiet zones.
  - On a 203-dpi thermal printer at 2 dots/module (X ≈ 9.85 mil), that is about 1.85 in wide, which fits a 2×1 in label with no margin to spare.
  - At 3 dots/module (X ≈ 14.8 mil), it is about 2.8 in, comfortable on a 4×6 or 3×2 tote label and very robust for LS2208-class scanners.
  - Use a bar height of at least 0.5 in. Printing the human-readable order number (not the payload) as separate large text helps the packers.
- **Use a real Code 128 encoder.** Use a proper encoder (e.g. bwip-js, JsBarcode, or ZPL `^BC`) rather than a font hack, so start, check and stop characters are correct. The ZPL caret problem below matters if you print ZPL.
- **ZPL caret gotcha:** `^` is ZPL's command prefix. When printing via ZPL, use `^CC` to change the caret character, or use `^FH` field-hex escaping (`_5E` for `^`, `_23` for `#`). Otherwise the printer reads the payload as commands. This is my own technical note, not from a ShipStation source.
- **Keyboard-wedge gotcha:** `^` and `#` are shifted keys, and on non-US keyboard layouts `^` can be a dead key. Keep the bench laptop on a US keyboard layout with the scanner in US keyboard emulation. This is my own technical note; the bench test will reveal it.

### Gaps
- No ShipStation official statement that third-party-printed Scan to View barcodes are supported. Evidence is community and third-party practice only.
- No Reddit or other independent second reproduction of the format was found. The format rests on one community post plus the Code128A consistency argument.
- **Bench test:** print an ERP-generated `^#^{HEX}^` label for a live Awaiting Shipment order, then check three things:
  1. It opens Order Details from an arbitrary ShipStation page (global listener).
  2. It opens the order on the Scan tab in Scan to Print and in Verify & Print.
  3. It reopens the shipment for reprint after the label is created.

## Q5. Edge cases: split, merged/combined, re-imports or edits, cancelled

### Takeaway
The barcode follows the ShipStation order record (orderId). Edits and store re-syncs keep the same order record, so the barcode stays valid; this is inferred. Splitting creates new order records with new orderIds. Combining keeps one surviving order and deletes the others, so their barcodes go dead. So the ERP must re-derive tote labels from the current order set after any split or combine, using `advancedOptions.mergedOrSplit`, `mergedIds` and `parentId` to detect them. Encoding orderId rather than orderNumber is correct, because split orders can share or suffix order numbers.

### Cited Findings
- **Split (legacy/manual) creates a new order:** "In the pop-up window, there will be a new order number with a suffix (such as -1 or -2)". "The split action will be logged in the order's Order Activity section, but the activity prior to the split will not be copied to the new order." For BigCommerce/Magento you "remove the -# suffix and retain the original order number". So split orders can end up with **identical order numbers**. — [Split Orders Into Multiple Shipments (updated 2026-08-27)](https://help.shipstation.com/hc/en-us/articles/360028798951-Split-Orders-Into-Multiple-Shipments)
- **Split Ship in the new layout:** shipments are shown "as (1 of 2), (2 of 2), and so on". After a split, "ShipStation will no longer import the marketplace status for that order. You will need to manually update the status of the ShipStation orders if the original order is shipped or cancelled on the marketplace side." — [Split Orders Into Multiple Shipments](https://help.shipstation.com/hc/en-us/articles/360028798951-Split-Orders-Into-Multiple-Shipments)
- **Combine:** "ShipStation will combine all selected orders and their items into a single surviving order, and the other orders will disappear from your Orders grid. These orders cannot be restored, though you can split the order into multiple orders again if necessary (this will result in new order records)." Also: "If using the [Order Number] field replacement … ShipStation will use the Order Number for the first order created." And you "must VOID the label first" if one exists. — [Combine Shipments](https://help.shipstation.com/hc/en-us/articles/360033432631-Combine-Shipments)
- **API flags:** `mergedOrSplit`, `mergedIds` and `parentId` (quoted in Q3). — [AdvancedOptions model](https://www.shipstation.com/docs/api/models/advanced-options/)
- **orderKey stability:** "Can only be initialized during order creation." — [Order model](https://www.shipstation.com/docs/api/models/order/)
- **Shopify split by default:** quoted in Q3. — [Shopify: Changes to Order Import](https://help.shipstation.com/hc/en-us/articles/47307773375387-Shopify-Changes-to-Order-Import)
- **Reship does not create a new order:** "Create Another Shipment does not create a new order". — [Reship an Order](https://help.shipstation.com/hc/en-us/articles/4417332306587-Reship-an-Order)

### Inferences
- **Edits and marketplace updates keep the same orderId**, so a previously printed tote label stays valid. `orderId` is system-generated and read-only, and `modifyDate` exists to track edits on the same record. No source explicitly states "orderId survives an edit", so I mark this "high-confidence inference".
- **Split orders:** the child order gets a new orderId (new record; `parentId` points back). A tote label printed before the split opens only the parent. The ERP should block or re-print tote labels when `mergedOrSplit` turns true.
- **Combined orders:** only the surviving orderId's barcode stays useful. The ERP should treat orderIds listed in another order's `mergedIds` as dead and re-label the tote with the survivor's barcode.
- **orderNumber is not unique** even within one store after a split (suffix removed) and across stores. This is a second reason to encode orderId.
- **Cancelled orders:** the barcode will most likely still open Order Details, because the record still exists. Whether the Scan tab refuses to print is undocumented; the ERP should not print tote labels for `orderStatus = cancelled`.

### Gaps
- **UNVERIFIED:** Scan tab behavior for cancelled, on-hold or already-shipped orders.
- **UNVERIFIED:** whether a "Split Ship" in the new layout (shipments "1 of 2") gives each shipment a distinct V1 orderId, or keeps one orderId with multiple shipments. The V1 `parentId` description implies separate records. **Bench test:** split a test order in the new layout and call `GET /orders?orderNumber=…` to see how many records come back and what their `orderId`/`parentId` values are.
- Whether a Shopify order edit (e.g. a line added after import) updates the same ShipStation order or creates a new one under the new Shopify fulfillment-order import pathway. Not documented.

## Q6. Alternative: ShipStation's own batch, pick-list and tote features

### Takeaway
ShipStation's pick lists carry no per-order barcode (as of the 2022 moderator answer). The standard fallback is to print packing slips (which carry the Scan to View barcode) without labels and use the slip as the tote ticket. ShipStation now has a native tote concept, but only inside its Mobile Picking feature. That feature requires ShipStation Inventory and warehouse locations, which would compete with the ERP's own inventory system, so it is not a good fit here.

### Cited Findings
- **Pick list has no barcode:** "To confirm, ShipStation does not currently support barcodes on the pick list but we are reviewing that idea!" (ShipStation moderator, 04-26-2022). The moderator adds that packing slips can be printed alone: "You can do this in bulk from the Orders grid by selecting the orders and from the PRINT drop down menu you can select packing slip." — [Pick List Order Number Barcode thread (Wayback)](http://web.archive.org/web/20250519203435/https://community.shipstation.com/t5/ShipStation-Features/Pick-List-Order-Number-Barcode/m-p/13177)
- **Order Summaries can also carry it:** The Scan to View barcode can be enabled on Order Summaries via Document Options. — [View Orders with a Barcode Scan](https://help.shipstation.com/hc/en-us/articles/360025870412-View-Orders-with-a-Barcode-Scan); [Order Summaries](https://help.shipstation.com/hc/en-us/articles/360025869912-Order-Summaries)
- **Scan to Batch uses the same barcode:** "The Scan to Batch feature allows you to scan the Scan to View barcode to quickly add additional orders to a batch." — [Batch Orders with a Barcode Scan](https://help.shipstation.com/hc/en-us/articles/360026936052-Batch-Orders-with-a-Barcode-Scan)
- **Native totes (Mobile Picking):** "you must first create and manage your totes in ShipStation". Totes live under Inventory Management Settings > Warehouses > Totes, where you can "Print Barcodes for existing tote(s)". — [Manage Totes for Mobile Picking (updated 2026-04-14)](https://help.shipstation.com/hc/en-us/articles/49132700371611-Manage-Totes-for-Mobile-Picking)
- **Pick to Tote requirements:** "Use Mobile Picking from ShipStation with a supported device", "Create and manage Totes in ShipStation", "Manage Inventory in ShipStation", "Manage Warehouse Locations", and "Maintain accurate SKUs and UPCs". — [Pick Using Batches](https://help.shipstation.com/hc/en-us/articles/49132678007451-Pick-Using-Batches); [The Picking Queue](https://help.shipstation.com/hc/en-us/articles/49132708418203-The-Picking-Queue)
- **Picking Queue order lookup:** "Search the order number or scan your packing slip barcode and click on the desired order." — [The Picking Queue](https://help.shipstation.com/hc/en-us/articles/49132708418203-The-Picking-Queue)
- **Supported devices:** "iOS Devices using version 15.0 or later. Android mobile phone or tablet on version 10.0 or later. Android-based barcode scanners. Bluetooth handheld scanners…". — [Introduction to Mobile Picking (updated 2026-09-07)](https://help.shipstation.com/hc/en-us/articles/49132708040347-Introduction-to-Mobile-Picking)
- **Plan requirement for custom templates:** "To create and edit packing slip templates, your account must be on a subscription plan that allows this feature. US, CA, UK, AU: Standard and Premium". The default packing slip, which includes the Scan to View barcode, "is available for all orders and for users on all plan levels". — [Add Barcodes to Packing Slips](https://help.shipstation.com/hc/en-us/articles/360060970712-Add-Barcodes-to-Packing-Slips); [Print Packing Slips](https://help.shipstation.com/hc/en-us/articles/360026157931-Print-Packing-Slips)

### Inferences
- **Zero-code fallback:** print ShipStation packing slips in bulk (no labels) for the orders the ERP releases to picking, and drop each slip in its tote. This works on Standard today, but it ties the pick flow to ShipStation printing and reintroduces paper matching. The ERP-printed `^#^{HEX}^` tote label replaces this and keeps the packers' Scan tab workflow identical.
- **ShipStation tote barcodes are a different thing.** They identify a physical tote inside ShipStation's Mobile Picking. Nothing indicates the Scan tab resolves a ShipStation tote barcode to an order, so they are not a substitute for the order barcode on the bench.

### Gaps
- Which plans include Mobile Picking and Totes is not stated in the articles reviewed.
- Whether ShipStation has since added barcodes to pick lists (the 2022 moderator said "reviewing that idea") is not confirmed in current docs.
